## 6. 结构创新路线复盘

### 6.1 初始 YoloCTM baseline

- `d_model=256, steps=4` 的原始 YoloCTM 在固定预算下表现很差：test macro F1 约 `0.62314`。
- 早期主要问题不是 CTM 没有信号，而是分类 head/训练选择目标与 long-tail macro F1 不匹配。
- Windows/启动方式曾造成多次 crash/hang，后来运行手册改为开发机本地前台终端、`workers=0`、固定日志。

### 6.2 有效方向

- **复用 YOLO classification head + CTM residual logits**：比完全替换 YOLO head 稳定，`d_model=96` 后参数更小。
- **按 validation macro F1 选 checkpoint**：明显优于仅看 accuracy，适合 WM811K long-tail 分类。
- **CTM feature adapter**：把 CTM token state 投影回 YOLO feature 后再过 YOLO head，是当前最有效的深融合方式。
- **Class-prior logit calibration**：`tau=0.4` 修复了 CTM adapter 过度提高 minority recall 导致 precision 下滑的问题，是单模型 F1 突破 baseline 的关键。

### 6.3 无效或负收益方向

- **过强压缩**：低秩 rank=32 减参到 `10.496M`，但 test macro F1 降到 `0.87796`，说明 adapter 容量不能简单压缩。
- **Balanced Softmax**：显著伤害 acc/F1，当前数据分布和 prior calibration 更适合后处理校准。
- **Attention readout / gated feature fusion / token spatial gate**：没有超过 CTM feature adapter + priorcal；可能引入了过多不稳定门控或破坏了 YOLO feature 的强先验。
- **Trainable prior bias**：优于若干失败分支但未达到最佳；训练中学习 prior correction 不如验证集选择固定 calibration 稳。
- **Anchor KL**：用 clean YOLO logits 约束 CTM adapter 未提升，可能限制了 CTM 的 minority recall 优势。

## 9. 下一阶段建议

1. **不要再单纯堆 ensemble**：ensemble 已证明上界，但参数量太大，应作为 teacher/误差分析工具。
2. **围绕最佳单模型做蒸馏/压缩**：尝试把 ensemble 的 log-prob 软标签或 per-class calibration 信息蒸馏到单个 CTM adapter 模型。
3. **保持低超参原则**：每轮只改一个结构点，继续固定 split/epoch/imgsz/batch。
4. **重点观察 macro precision 与 recall 的平衡**：目前 CTM 往往拉 recall，calibration 拉 precision，下一步应避免某一端崩掉。
5. **优先做错误互补分析**：比较 YOLO26m、CTM adapter、low-rank adapter 在 minority 类上的错误，找可压缩到单模型的机制。
6. **记录规范继续保留**：每次结构代码先 commit，每次实验结束必须写 `AutoResearch/results.tsv` 和 `AutoResearch/logs/*.json`。
